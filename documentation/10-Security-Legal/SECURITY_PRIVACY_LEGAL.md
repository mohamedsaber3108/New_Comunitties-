# Security, privacy and legal readiness

## Implemented controls

Password hashing; random opaque server sessions stored by SHA-256 token hash; httpOnly/SameSite cookies; Secure production cookie; same-origin mutation check; basic login/signup/contact throttling; input lengths; React escaping; owner/admin checks; opt-in discoverability and messaging; shared-community messaging; blocks; report queue; admin audit entries; no seeded admin secret.

## Open security work

Email verification/reset, MFA, CSRF token strategy, durable distributed rate limiting, media scanning/validation, content-security policy, device/session UI, tenant authorization, abuse heuristics, incident process, centralized logs/metrics/traces, backup restore drill, secret rotation, dependency remediation, SAST/DAST and production penetration testing.

## Privacy/data lifecycle work

Self-service export/deletion, retention schedules, lawful-basis register, consent records, processor/subprocessor inventory, cross-market assessment, data residency, cookie choices, marketing preferences, partner disclosure and incident notification workflow are missing. Public legal text is informational product copy and must be reviewed by qualified counsel for the actual Egypt and expansion markets before launch.

Tenant-filtered retrieval, citations, prompt/tool allowlists, input/output logging with redaction, per-plan budgets, provider fallback, prompt-injection tests and human approval for consequential actions. No live AI gateway exists in this source.
